Reading checkpoint

¿Qué equivale en C# al __init__ de Python?

public Cuenta(string titular) { ... } se ejecuta con new Cuenta("Ana").

¿Qué equivale a self?

En C# los campos y métodos del propio objeto se usan directo; this.saldo es opcional salvo que haya un parámetro con el mismo nombre.

Un campo declarado private decimal saldo;…

En Python el guion bajo es un acuerdo; en C# private lo hace cumplir el compilador.

¿Qué es public decimal Saldo { get; private set; }?

Es el equivalente de @property sin setter público.

¿Qué ventaja tiene List<decimal> sobre decimal[]?

Un arreglo se crea con un tamaño que no cambia. List<T> es como la lista de Python, pero solo acepta el tipo T.

Para que una clase hija pueda redefinir CalcularPago(), en la clase base el método debe ser…

En Python cualquier método se puede redefinir; en C# se declara explícitamente la intención con virtual/override.

¿Qué hace : base(nombre, 0) en el constructor de una clase hija?

Es la misma idea de la semana 9 con otra sintaxis.

Clases, campos y propiedades

En palabras simples

La cuenta bancaria de la semana 8 es la misma; solo cambia el idioma. C# te pide decir en voz alta lo que en Python era una convención: qué es privado, qué se puede leer y qué tipo tiene cada cosa.

Caso: la CuentaBancaria de la semana 8 en C#

Pregunta

¿Cómo se expresa en C# una cuenta cuyo saldo solo cambia con depósitos y retiros válidos?

Exploración
  • self._saldo + @property → public decimal Saldo { get; private set; }
  • raise ValueError → throw new ArgumentException(...)
  • except ValueError as e → catch (ArgumentException ex)
Implementación 
var ana = new Cuenta("Ana", 100m);
ana.Depositar(50m);
ana.Retirar(30m);
Console.WriteLine($"{ana.Titular}: {ana.Saldo:F2}");

try
{
    ana.Retirar(500m);
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"Rechazado: {ex.Message}");
}
// ana.Saldo = 1000m;   // no compila: el set es privado (CS0272)


public class Cuenta
{
    private readonly List<string> movimientos = new();

    public string Titular { get; }
    public decimal Saldo { get; private set; }

    public Cuenta(string titular, decimal saldoInicial = 0m)
    {
        if (saldoInicial < 0)
            throw new ArgumentException("el saldo inicial no puede ser negativo");
        Titular = titular;
        Saldo = saldoInicial;
    }

    public void Depositar(decimal monto)
    {
        if (monto <= 0)
            throw new ArgumentException("el depósito debe ser positivo");
        Saldo += monto;
        movimientos.Add($"depósito {monto:F2}");
    }

    public void Retirar(decimal monto)
    {
        if (monto <= 0)
            throw new ArgumentException("el retiro debe ser positivo");
        if (monto > Saldo)
            throw new InvalidOperationException($"saldo insuficiente ({Saldo:F2})");
        Saldo -= monto;
        movimientos.Add($"retiro {monto:F2}");
    }
}
Ana: 120.00
Rechazado: saldo insuficiente (120.00)
Interpretación

Titular { get; } solo se asigna en el constructor. Saldo se lee desde afuera, pero su set es privado: la línea comentada no compilaría. La protección que en Python era una convención aquí la garantiza el compilador.

Verificación

100 + 50 − 30 = 120 ✔; el retiro de 500 se rechaza y el saldo queda en 120. Mismo comportamiento que la clase de la semana 8.

Convenciones de nombres en C#
  • Clases, métodos y propiedades: PascalCase (Depositar, Saldo).
  • Campos privados y variables locales: camelCase (movimientos, saldoInicial).
  • Una clase pública por archivo en proyectos reales (Cuenta.cs).

Arreglos y List<T>

En palabras simples

Un arreglo es una caja de huevos: trae 12 espacios y no más. Una List<T> es una bolsa con etiqueta: crece lo que necesites, pero solo acepta lo que dice la etiqueta.

decimal[] fijos = { 12.50m, 4.25m, 3.90m };        // arreglo: tamaño fijo
Console.WriteLine($"Arreglo: {fijos.Length} precios, primero {fijos[0]}");

var precios = new List<decimal> { 12.50m, 4.25m };
precios.Add(3.90m);
precios.Add(6.75m);
precios.Remove(4.25m);
precios.Insert(0, 1.99m);
Console.WriteLine($"Lista: {string.Join(", ", precios)} ({precios.Count} elementos)");

decimal total = 0;
foreach (decimal p in precios)
{
    total += p;
}
Console.WriteLine($"Total: {total:F2}  ¿Contiene 3.90? {precios.Contains(3.90m)}");

precios.Sort();
Console.WriteLine($"Ordenados: {string.Join(", ", precios)}");

var productos = new List<Producto>
{
    new Producto("A01", "Aceite", 12.50m, 40),
    new Producto("B07", "Arroz", 4.25m, 8),
};
foreach (var p in productos)
{
    if (p.Stock < 10) Console.WriteLine($"Reordenar {p.Nombre}");
}

    public string Nombre { get; }

    {
        Codigo = codigo;
        Nombre = nombre;
        Precio = precio;
        Stock = stock;

}

Herencia y polimorfismo en C#

En palabras simples

Es la planilla de la semana 9. La diferencia: en C# la clase base avisa qué se puede redefinir (virtual) y la hija declara que lo redefine (override). Nada pasa por accidente.

Caso: la planilla polimórfica de la semana 9

Pregunta

¿Se puede demostrar que el diseño de la semana 9 es independiente del lenguaje?

Implementación 
var planilla = new List<Empleado>
{
    new Empleado("Ana", 900m),
    new PorHora("Luis", 4.5m, 170),
    new Vendedor("Eva", 500m, 12000m),
};

decimal total = 0;
foreach (Empleado e in planilla)          // polimorfismo
{
    Console.WriteLine($"{e.Nombre,-6} {e.GetType().Name,-9} {e.CalcularPago(),9:N2}");
    total += e.CalcularPago();
}
Console.WriteLine($"Total planilla: {total:N2}");


public class Empleado
{
    public string Nombre { get; }
    protected decimal SalarioBase { get; }

    public Empleado(string nombre, decimal salarioBase)
    {
        Nombre = nombre;
        SalarioBase = salarioBase;
    }

    public virtual decimal CalcularPago() => SalarioBase;
}

public class PorHora : Empleado
{
    private readonly decimal tarifa;
    private readonly int horas;

    public PorHora(string nombre, decimal tarifa, int horas) : base(nombre, 0m)
    {
        this.tarifa = tarifa;
        this.horas = horas;
    }

    public override decimal CalcularPago()
    {
        decimal extra = Math.Max(0, horas - 160) * tarifa * 0.5m;
        return horas * tarifa + extra;
    }
}

public class Vendedor : Empleado
{
    private readonly decimal ventas;

    public Vendedor(string nombre, decimal salarioBase, decimal ventas) : base(nombre, salarioBase)
    {
        this.ventas = ventas;
    }

    public override decimal CalcularPago() => base.CalcularPago() + ventas * 0.05m;
}
Ana    Empleado     900.00
Luis   PorHora      787.50
Eva    Vendedor   1,100.00
Total planilla: 2,787.50
Interpretación

: base(nombre, 0m) = super().__init__(nombre, 0). protected: visible para las hijas, no para el resto. => define un método de una sola expresión. La lista es List<Empleado> y guarda objetos de las tres clases: polimorfismo.

Verificación

Mismos números que en Python: 900.00, 787.50, 1,100.00 y total 2,787.50 ✔. Esta equivalencia es lo que el programa llama “demostración de equivalencia semántica entre lenguajes”.

E1 · Estudiante con notas, en C#

clase + List + propiedades · ★★

Traduce la clase Estudiante de la semana 8: lista privada de notas, validación de 0 a 10, Promedio y Aprobado como propiedades calculadas, y ToString() (el __str__ de C#).

Solución
var e = new Estudiante("Carla", "2026-0412");
e.AgregarNota(7.5m);
e.AgregarNota(5.0m);
e.AgregarNota(8.0m);
Console.WriteLine(e);
try { e.AgregarNota(11m); }
catch (ArgumentOutOfRangeException ex) { Console.WriteLine($"Error: {ex.ParamName} fuera de rango"); }


public class Estudiante
{
    private readonly List<decimal> notas = new();
    public string Nombre { get; }
    public string Carnet { get; }

    public Estudiante(string nombre, string carnet)
    {
        Nombre = nombre;
        Carnet = carnet;
    }

    public void AgregarNota(decimal nota)
    {
        if (nota < 0 || nota > 10)
            throw new ArgumentOutOfRangeException(nameof(nota));
        notas.Add(nota);
    }

    public decimal Promedio => notas.Count == 0 ? 0 : Math.Round(notas.Sum() / notas.Count, 2);
    public bool Aprobado => Promedio >= 6;

    public override string ToString() =>
        $"{Carnet} {Nombre}: {Promedio} ({(Aprobado ? "aprobado" : "en riesgo")})";
}
2026-0412 Carla: 6.83 (aprobado)
Error: nota fuera de rango

override string ToString() hace que Console.WriteLine(e) muestre el objeto en términos del negocio. notas.Sum() suma la lista.

E2 · Formas de pago con clase abstracta

abstract + override · ★★★

Traduce el simulador de pagos de la semana 9. La clase base es abstract: declara Comision sin implementarla y obliga a cada hija a hacerlo.

Solución
var metodos = new List<MetodoPago> { new Efectivo(), new Tarjeta(), new Transferencia() };
foreach (var m in metodos)
{
    Console.WriteLine($"{m.GetType().Name,-13} cobra {m.Cobrar(80m):F2}");
}


public abstract class MetodoPago
{
    public abstract decimal Comision(decimal monto);
    public decimal Cobrar(decimal monto) => monto + Comision(monto);
}

public class Efectivo : MetodoPago
{
    public override decimal Comision(decimal monto) => 0m;
}

public class Tarjeta : MetodoPago
{
    public override decimal Comision(decimal monto) => Math.Round(monto * 0.035m, 2);
}

public class Transferencia : MetodoPago
{
    public override decimal Comision(decimal monto) => monto < 100 ? 0.75m : 0m;
}
Efectivo      cobra 80.00
Tarjeta       cobra 82.80
Transferencia cobra 80.75

Si una hija olvida implementar Comision, el programa no compila (en Python, el NotImplementedError aparecía al ejecutar). Otra vez el compilador te cuida.

public class Producto
{
    public string Codigo { get; }
    public string Nombre { get; }
    public decimal Precio { get; }
    public int Stock { get; private set; }

    public Producto(string codigo, string nombre, decimal precio, int stock)
    {
        if (precio <= 0) throw new ArgumentException("precio inválido");
        Codigo = codigo; Nombre = nombre; Precio = precio; Stock = stock;
    }

    public void Vender(int cantidad)
    {
        if (cantidad <= 0 || cantidad > Stock)
            throw new InvalidOperationException($"no hay {cantidad} de {Nombre} (quedan {Stock})");
        Stock -= cantidad;
    }
}

public class Inventario
{
    private readonly List<Producto> productos = new();

    public void Agregar(Producto p)
    {
        if (Buscar(p.Codigo) != null)
            throw new ArgumentException($"código repetido: {p.Codigo}");
        productos.Add(p);
    }

    public Producto? Buscar(string codigo)
    {
        foreach (var p in productos)
            if (p.Codigo == codigo) return p;
        return null;
    }

    public void Vender(string codigo, int cantidad)
    {
        Producto p = Buscar(codigo) ?? throw new ArgumentException($"no existe {codigo}");
        p.Vender(cantidad);
    }

    public decimal Valor()
    {
        decimal total = 0;
        foreach (var p in productos) total += p.Precio * p.Stock;
        return total;
    }

    public List<Producto> PorReordenar(int minimo)
    {
        var resultado = new List<Producto>();
        foreach (var p in productos)
            if (p.Stock < minimo) resultado.Add(p);
        return resultado;
    }
}
Rechazado: no hay 20 de Arroz 5 lb (quedan 8)
Rechazado: código repetido: A01
Valor del inventario: 471.50
Reordenar: Arroz 5 lb (8)
Reordenar: Azúcar 5 lb (0)

Verificación: 35 × 12.50 + 8 × 4.25 + 0 = 437.50 + 34 = 471.50 ✔.
