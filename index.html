Cómo estudiar con esta guía

El curso es aula invertida: el libro es la primera fuente y la clase es laboratorio. Antes de cada sesión hay un control de lectura en Moodle, y la clase arranca con preguntas difíciles. Cada semana está pensada para cuatro momentos:

Antes de claseLecturas asignadas y el control de lectura de la semana.
En el laboratorioReferencia rápida junto a VS Code: comandos, patrones, sintaxis.
Después de claseTrazas a mano y ejercicios; abre la solución solo después de intentarlo. Los bloques de Python tienen botón Correr y Editar: pruébalos y cámbialos ahí mismo.
Antes de evaluarListas “puedo…”, auditorías y preguntas de defensa.

El ciclo de cada tema

Todos los conceptos se resuelven con el mismo ciclo. Es la forma de resolver un problema real y también la forma de defenderlo:

Pregunta¿Qué necesita el negocio? ¿Qué decisión depende de esto?
Exploración¿Cuáles son las entradas, las salidas, las reglas y las fronteras?
Implementación¿Cómo se escribe: pseudocódigo, diagrama, código?
Resultado¿Qué produce exactamente?
Interpretación¿Qué significa ese número para quien decide?
Verificación¿Cómo sé que es correcto? Traza, cálculo independiente, casos borde, pruebas.
Regla de progresión Ninguna semana usa algo que el curso enseña después. Cada página empieza con “qué puedes usar / todavía no”. Lo que se adelanta está marcado como adelanto opcional y no entra en la evaluación.

Reglas que conviene no olvidar
  • IA: prohibida en controles y exámenes. En tareas y proyecto, todo uso se declara en el README y debes poder defender cada línea; si no puedes explicar una solución, se anula la entrega.
  • Asistencia: mínimo 80 % para tener derecho al proyecto final y al examen.
  • Puntualidad: pasados 10 minutos no se permite el ingreso.
  • Plagio: el código copiado o no atribuido se remite al Comité Disciplinario.
