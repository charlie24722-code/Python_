Cómo estudiar con esta guía

El curso es aula invertida: el libro es la primera fuente y la clase es laboratorio. Antes de cada sesión hay un control de lectura en Moodle, y la clase arranca con preguntas de alta complejidad. Esta guía está hecha para cuatro momentos:

Antes de claseLecturas asignadas + reading checkpoint de la semana.
Durante el laboratorioReferencia rápida junto a VS Code: comandos, patrones, sintaxis.
Después de claseTrazas a mano y ejercicios; abre la solución solo después de intentarlo.
Antes de evaluarListas “puedo…”, auditorías y preguntas de defensa del proyecto.

El ciclo de cada tema

Todos los conceptos se presentan con el mismo ciclo. Es la forma de resolver un problema real y la forma de defenderlo:

PasoLa pregunta que te haces
1. Pregunta¿Qué necesita el negocio? ¿Qué decisión depende de esto?
2. Exploración¿Cuáles son las entradas, las salidas, las reglas y las fronteras?
3. Implementación¿Cómo se escribe (pseudocódigo, diagrama, código)?
4. Resultado¿Qué produce exactamente?
5. Interpretación¿Qué significa ese número para quien decide?
6. Verificación¿Cómo sé que es correcto? Traza, cálculo independiente, casos borde, pruebas.
Regla de progresión Ninguna semana usa algo que el curso enseña en una semana posterior. Cada página empieza con un cuadro de “qué puedes usar / todavía no”. Si aparece algo de más adelante, está marcado como adelanto opcional y no es necesario para evaluar.

Evaluación

Ponderación

Examen Parcial25 %
Examen Final25 %
Controles20 %
Proyecto integrador30 %

La nota del proyecto solo se suma si alcanzas la nota mínima en las evaluaciones individuales (controles y exámenes). Un buen proyecto no compensa un rendimiento individual insuficiente.

Rúbrica del proyecto

Arquitectura de software y POO25 %
Lógica algorítmica, robustez y persistencia25 %
Pruebas automatizadas y buenas prácticas (Git, PEP 8)25 %
Defensa oral individual y criterio de negocio25 %

Cada integrante debe poder explicar y modificar en vivo cualquier parte del código. Por eso cada semana trae preguntas de defensa.

Reglas que conviene no olvidar
  • IA: prohibida en controles y exámenes. En tareas y proyecto, todo uso se declara en el README y debes poder defender cada línea; no poder explicar una solución anula la entrega.
  • Asistencia: mínimo 80 % para tener derecho al proyecto final y al examen.
  • Puntualidad: pasados 10 minutos no se permite el ingreso.
  • Plagio: código no atribuido o copiado se remite al Comité Disciplinario.
